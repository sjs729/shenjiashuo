01

为什么要做降级

答辩要求写出理由。这不是"可选优化"，而是必经分支。

三个硬事实

① 电脑浏览器没有加速度计，devicemotion 要么不触发、要么给的三个值全是 null；
② iOS 13+ 出于隐私，必须用户点击后调用 DeviceMotionEvent.requestPermission()， 不能在页面加载时自动申请；
③ 用户可能直接点"拒绝"，之后这个页面永远收不到数据。 三条里任意一条成立，页面就会静默失效——不写降级就是白屏。

本页的降级策略

检测不到 devicemotion、或 3 秒内没有收到任何数据、或权限被拒， 就显示提示并把"点我抽一次"按钮变成主路径。 功能不打折，只是换一种触发方式。
02

两个 API 的区别

答辩第四问会问这个，别混。

accelerationIncludingGravity vs acceleration

前者含重力：手机平放桌上不动，Z 轴也约等于 9.8，因为它在测重力。
后者不含重力：静止时三个轴都接近 0，只有真正被加速时才非零。

所以：判断"摇一摇"用前者更稳——静止时基线固定（约 9.8）， 摇动的峰值一眼能看出；用后者虽然静止时更干净，但部分安卓机直接把该字段置为 null， 兼容性反而差。

为什么还要算"合成加速度"

三个轴分别是 x / y / z，摇动方向不确定。取
Math.sqrt(x² + y² + z²)
才是"整体受力大小"，与方向无关。这就是阈值判断的依据。
03

冷却为什么必须加

不加冷却，一次摇动会触发十几次——因为 devicemotion 是持续高频触发的。

现象

甩一下手机，devicemotion 可能连续触发 30～60 次， 每次都超过阈值。如果每次超阈值都抽一次，你会看到菜名疯狂闪动，最后停在某个随机结果上。

做法

记录上次触发的时间戳，本次超阈值时先看间隔： 小于 1.5 秒就直接返回，不抽也不改状态。 这和任务二"防止连滑跳两张"是同一个思路——用时间做节流。
04

核心代码

// ① iOS 13+ 必须由用户点击触发权限申请
btnPerm.addEventListener('click', async function () {
  if (typeof DeviceMotionEvent.requestPermission === 'function') {
    const state = await DeviceMotionEvent.requestPermission();
    if (state !== 'granted') { showFallback('权限被拒绝'); return; }
  }
  startListen();
});

// ② 监听加速度
window.addEventListener('devicemotion', function (e) {
  const a = e.accelerationIncludingGravity;
  if (!a) return;                                   // 部分设备给 null

  // ③ 合成加速度：与摇动方向无关
  const total = Math.sqrt(a.x*a.x + a.y*a.y + a.z*a.z);

  // ④ 冷却：1.5 秒内只认第一次
  if (total > 18 && Date.now() - lastShake > 1500) {
    lastShake = Date.now();
    roll();                                         // 抽一道菜
  }
});
05

怎么在电脑上验证

电脑没有传感器，但可以用 Chrome DevTools 伪造加速度数据。

步骤

① F12 → 右上角三个点 → More tools → Sensors；
② 找到 Accelerometer，从 "No override" 改成 "Custom"；
③ 在 X / Y / Z 里填一组大数值（比如各填 30）， 合成加速度 √(30²+30²+30²) ≈ 52，远超阈值 18；
④ 页面会自动抽一道菜，并进入 1.5 秒冷却。

注意：伪造的是持续值，所以"摇一次"会变成"持续满足条件"—— 正好用来验证冷却是否生效：如果菜名没有连续闪动，说明冷却起作用了。
