绑成一套

02

能调的不是方向，是跟随行为

我一开始以为它只有"点缩略图切主图"这一个方向，翻源码才发现它天生是双向的： 模块内部监听主图的 slideChange，主图一变就调 update() 把缩略图拨过去。 所以能调的其实不是方向，而是缩略图跟随时的行为。下面三档是这个参数的不同取值。

模式 关键配置 现象
标准跟随 thumbs: { swiper } 点缩略图主图跳；主图翻页时缩略图也自动跟过去，激活类同步点亮
缩略图自由滑动 缩略图加 freeMode: true 可以拖着缩略图条连续滑，不必一张一张卡位，联动依旧生效
缩略图偏移跟随 thumbs.autoScrollOffset: 1 缩略图被推得比主图多一格，当前项不在最左边而在第二位
03

它到底是怎么绑的

关键在这一句：thumbs: { swiper: 缩略图实例 }。注意——它传的是实例，不是选择器。 这意味着必须先 new 出缩略图，再把那个对象交给主图。

顺序不能反

先创建缩略图实例，再创建主图实例，并把缩略图对象传进去。反过来的话主图拿不到引用，联动直接失效。

  • ① new Swiper('#sjsThumbs', {...})
  • ② new Swiper('#sjsMain', { thumbs: { swiper } })

两个容易漏的配置

缩略图要加 watchSlidesProgress: true，否则它不知道每张滑到哪； 再用 slidesPerView: 'auto' 让缩略图按自身宽度排布。

  • spaceBetween 控制缩略图间距
  • .swiper-slide-thumb-active 是同步时自动加的类
// ① 先建缩略图：它是被"引用"的一方
var sjsThumb = new Swiper('#sjsThumbs', {
  spaceBetween: 8,
  slidesPerView: 'auto',
  watchSlidesProgress: true   // 没有它，缩略图不知道自己滑到哪
});

// ② 再建主图：把缩略图实例交给 thumbs
var sjsMain = new Swiper('#sjsMain', {
  navigation: { nextEl: '#sjsNext', prevEl: '#sjsPrev' },
  thumbs: { swiper: sjsThumb }   // ← 传对象，不是选择器字符串
});
答辩原话："thumbs 的本质不是新效果，是把两个实例的 slideTo 互相接上。 所以要传实例而不是选择器——Swiper 需要在运行时调用那个对象的方法来同步索引。 缩略图必须加 watchSlidesProgress，否则它没法判断当前滑到第几张，同步就断在这。"
04

为什么不用一个实例硬做

可能有人会想：用一个 Swiper，下面放一排小图当分页器不就行了？技术上可以，但要自己写一堆同步逻辑。

做法 实现方式 代价
thumbs 双实例 thumbs 配置一行搞定 几乎为零，Swiper 内部处理同步
自定义分页器 自己生成小图、监听点击、手动 slideTo 缩略图条不能滑动、无法处理溢出
单实例硬塞 把缩略图当 slide 内容的一部分 高度、比例全乱，主图与缩略图共用一个 slide 尺寸
