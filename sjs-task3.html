03

键盘到底挂在哪

这是我最想讲清楚的一点，也是答辩时最容易答错的地方。键盘监听不在轮播容器上，在 document 上。

它监听的是整个文档

Swiper 的 keyboard 模块在 init 时执行 document.addEventListener('keydown', handle)。 所以焦点在不在轮播上，其实都能收到按键——我实测过：焦点停在 body， 轮播在视口内，按 → 照样翻页。

  • 不是「只对已聚焦容器生效」
  • 不是「必须 tabindex 才能翻」
  • tabindex 只影响视觉提示，不影响功能

真正拦你的是 onlyInViewport

它默认是 true。每次按键前会算容器四角坐标，四个角都不在窗口内就直接 return——这就是"滚出屏幕后按键没反应"的原因，是防误触，不是 bug。

  • 还有：焦点在 input / textarea 里时不响应
  • 还有：按住 Shift / Alt / Ctrl / Cmd 时不响应
  • 还有：按的是 ↑↓ 时，横向轮播不响应
// 我写的初始化（只挑了必要项）
new Swiper('#sjsSwShow', {
  effect: 'slide',
  loop: true,
  keyboard: {
    enabled: true,        // 开启键盘
    onlyInViewport: true  // 默认值，写出来是为了强调它
  },
  pagination: { el: '#sjsPagShow', clickable: true },
  navigation: { prevEl: '#sjsPrevShow', nextEl: '#sjsNextShow' }
});
答辩原话："keyboard 的 keydown 挂在 document 上，所以不需要聚焦也能用。 真正决定按了有没有反应的是 onlyInViewport，它默认 true，会算容器四角坐标， 四个角都不在视口内就 return。我加 tabindex 只是为了点一下能有聚焦描边， 让使用者知道'现在可以按方向键'——去掉它功能照样跑。"
04

为什么没选 parallax 和 zoom

讲解版给了四个选项：keyboard / mousewheel / zoom / parallax。选 keyboard 不是因为它炫，是因为它能讲出原理。

另外三个的取舍

  • mousewheel：滚轮翻页会和页面滚动打架，在长页面里体验很差
  • zoom：双击缩放需要图片支持放大，六张图尺寸不一致时观感不统一
  • parallax：视差要配合 data-swiper-parallax 分层，改造成本高，效果偏暗

keyboard 的优势

  • 零视觉改动，不破坏现有展陈风格
  • 可访问性加分：不用鼠标也能翻页
  • 参数少但有细节，经得起追问
  • 开关一摆，现场就能演示差异
