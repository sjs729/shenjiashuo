01

怎么保证"缩放不跳"

这是本任务最核心的问题，也是答辩必问。答案不是"算得准"，而是换算顺序。

问题出在哪

缩放如果只改 scale，图片是围着自身中心放大的。 但你的手指可能按在图片左上角——那一刻你会看到图片"往右下窜"，离开手指。 因为放大中心和你按下的位置不是同一个点。

做法：先补偿位移，再改缩放

把两指中点记为基准点 (px, py)。缩放比例从 s1 变成 s2 时， 要让基准点在屏幕上的位置保持不动，位移必须这样补：

tx2 = px - (px - tx1) × (s2 / s1)
ty2 = py - (py - ty1) × (s2 / s1)

直观理解：基准点离图片中心的距离，要跟着缩放比例一起缩放， 这样基准点才原地不动。纵向同理。

三个必须做的收尾

① touchmove 里要 preventDefault()，否则整页跟着放大（需要 { passive: false }）；
② 每次新手势开始（touchstart）要清掉上一轮的"上一帧距离"，否则第一帧拿残留值比较会跳一下；
③ 松手后要限制边界，不能让图片被拖出可视区；缩回 1x 时自动居中。
02

双指缩放的核心代码

// 两指距离（勾股定理）
function sjs_dist(a, b) {
  return Math.hypot(b.clientX - a.clientX, b.clientY - a.clientY);
}

sjs_viewer.addEventListener('touchmove', function (e) {
  // 双指：算缩放
  if (e.touches.length === 2) {
    e.preventDefault();               // 阻止整页缩放（需 passive: false）

    const d = sjs_dist(e.touches[0], e.touches[1]);
    // 两指中点 = 缩放基准
    const px = (e.touches[0].clientX + e.touches[1].clientX) / 2;
    const py = (e.touches[0].clientY + e.touches[1].clientY) / 2;

    if (sjs_lastDist) {
      const ratio = d / sjs_lastDist;             // 本帧缩放比例
      const next  = sjs_clamp(sjs_scale * ratio, 1, 4);

      // 关键：先按新比例补偿位移，再赋值
      sjs_tx = px - (px - sjs_tx) * (next / sjs_scale);
      sjs_ty = py - (py - sjs_ty) * (next / sjs_scale);
      sjs_scale = next;

      sjs_apply();
    }
    sjs_lastDist = d;
  }
}, { passive: false });

为什么 px 要用页面坐标而不是图片坐标

位移 tx / ty 是加在
translate(-50%, -50%) translate(tx, ty) scale(s) 这一串里的，它作用在屏幕坐标系上。 所以基准点也必须用屏幕坐标（clientX/Y），两者才能对上。
03

边界与回弹

放大后可以拖，但不能拖出边界；缩回 1x 时自动回到中心。

边界怎么算

缩放后图片的显示宽度 = 原始宽度 × scale。 如果它比容器宽，最多能拖动 (显示宽度 − 容器宽度) / 2； 如果比容器窄，就不允许横向拖动（tx 强制为 0）。纵向同理。

松手时的处理

touchend 里做一次"夹紧"：把 tx / ty 限到允许范围内， 并短暂打开过渡（data-anim="1"），让回弹有个 0.25s 的动画， 而不是硬生生跳回去。动画结束再关掉过渡，保证下一次拖动仍然是瞬时的、跟手的。
04

双击的两次判断

双击不是"连续两次 touchstart"，而是两次完整的点按，间隔小于 300ms。

为什么要判断间隔

如果不判断间隔，用户隔三秒点两次也会被当成双击。 做法是记录上一次抬起的时间戳 sjs_lastTap， 本次抬起时看差值是否小于 300ms。

触发后要重置

双击成立后把 sjs_lastTap 清零， 否则连点三下会被算成"两次双击"。这和轮播里"防止跳两张"是同一类思路。
