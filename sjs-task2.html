02

每个滑杆在拧什么

答辩时被追问"这个数改了会怎样"，照着下面答就行——这些都不是背来的，是刚才拖出来的。

prev 管"已经翻过去那张"

它的 progress 是正数。写进去的位移、深度、角度，会按它离当前页有多远来打折扣： translate 是 目标值 × 进度，所以第一张刚退走时完全展开，越远越收敛。

prev: {
  translate: [-38%, 0, -320],
  rotate: [0, 0, -8],
  shadow: true
}

X 给负值 → 往左退；Z 给负值 → 往远处缩（透视下看起来更小）；rotate[2] 给负值 → 逆时针歪。

next 管"还没轮到那张"

它的 progress 是负数。同样按进度插值，只是方向相反：从右边推进来、从远处放大过来。 把 opacity 调低，它就会先隐身再浮现。

next: {
  translate: [100%, 0, 120],
  scale: 0.86,
  opacity: 0
}

X 给正值 → 停在右侧等进场；Z 给正值 → 略靠前；scale 小于 1 → 进场时由小放大。

为什么"电影墙"好看：它同时用了三件事——退场那张缩小 + 后退营造纵深， 歪 8 度打断整齐感（电影选片墙上的海报不会是正的）， 进场那张从右侧推进并带缩放，让人感觉"下一张正在被递过来"。 只做位移不做纵深，看起来就像普通的平推。
03

那个百分号，到底是相对谁

这是我踩过的坑。第一版我以为它相对容器宽高，还把它写进了注释——后来实测发现是错的，这里留一份证据。

实验设置

容器宽 600px，slidesPerView: 3，所以每张 slide 宽 200px。 把 translate 的 X 设成 '50%'，然后读实际位移量。

容器宽 = 600px
slide 宽 = 200px
translate: ['50%', 0, 0]
→ 实测位移 100px

100px = 200 × 50%，也就是 slide 的宽度。如果相对容器，应该是 300px。

为什么是这样

Swiper 拼出来的字符串长这样：calc(50% - 200px)，然后赋给这张 slide 自己的 transform。CSS 规范里，translate 的百分比基准是元素自身的盒子尺寸， 所以它认的是 slide，不是容器。

translate3d(calc(50% - 200px), 0, 0)
       ↑
50% 按 slide 宽 200px 算 → 100px
再减 200px 的槽位偏移 → 净 -100px

这也解释了为什么 slidesPerView 一改，同样的百分比写法效果会变——基准跟着 slide 走了。

答辩原话："百分号相对的是这张 slide 自己的宽度，不是容器，也不是里面的图片。 容器 600、一屏三张时 slide 只有 200，写 50% 只位移 100px。 证据是 Swiper 把参数拼成了 calc(50% - 200px) 这种字符串，直接赋在 slide 的 transform 上。"
04

三个必答问题

老师在答辩里问得最多的三个，按顺序准备。

Q1 · prev / next 的 transform 各控制什么？

prev 控制"已经翻过去的那张"要退到哪、歪成什么样； next 控制"还没轮到的那张"待在哪、怎么进场。 两者都是相对当前 slide 的姿态，按各自的 progress 插值。

Q2 · 改一个数值让卡片转 20 度？

把 rotate 第三项改成 20：rotate: [0, 0, 20]。 单位是度，不写 deg。实测 matrix 解出来的角度正好 20.00°。 绕 Z 轴转就是平面内旋转，最直观。

Q3 · 为什么换 effect 必须销毁重建？

effect 只在 init 阶段读一次参数，之后改 params.effect 不会重新挂载模块。 所以要 destroy() 再 new，并且重建前要清掉 cube 残留的 .swiper-cube-shadow，否则容器会被撑高。
